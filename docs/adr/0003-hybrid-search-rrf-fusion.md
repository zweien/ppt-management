# ADR-0003:混合检索融合 —— RRF + 结构化加分

- **状态**:已接受
- **日期**:2026-07-29
- **决策者**:工程讨论确认
- **取代**:无

## 背景

PRD §8.3 要求混合检索(全文 + 向量 + 标签 + 时间),并给出加权公式:

```
final_score = 0.50 × text_score + 0.30 × vector_score + 0.15 × tag_score + 0.05 × recency_score
```

并要求"先将各召回分数归一化"。但这里有一个**数学硬伤**:`ts_rank_cd`(全文)返回的是词频相关度,范围不固定(0.x 到几十);pgvector 的 cosine 距离是 `0~2`。两种分数**量纲完全不同**,直接线性相加在数学上是错的——词频高的页面会碾压向量分。"归一化"看似解决,但 min-max/z-score 归一化依赖整个结果集统计量,在分页(只取前 24 条)时会导致翻页分数跳变。

此外 PRD §8.3 还有一组业务意图需要保留:文本为主、文件名/标题精确匹配额外加分、人工标签优先级高于 AI 标签、"我的素材优先"模式加权。

## 决策

### 主体排序:RRF(Reciprocal Rank Fusion)

不用绝对分数,只用**排名**。公式:

```
score(d) = Σ 1 / (k + rank_i(d))
```

- `k = 60`(经验默认,偏保守)。
- 每路召回独立取 **top-100**,融合后返回前 24。
- 融合前各路召回的绝对分数被丢弃,只保留排名。

### 结构化加分(additive bonus)

RRF 决定基础排序后,以下规则作为**加性 bonus** 叠加在 RRF 分数上:

- 文件名 / 页面标题精确匹配 → bonus
- 人工标签匹配(权重高于 AI 标签)→ bonus
- "我的素材优先"模式(收藏页加权)→ bonus

```
final = rrf_score(text_rank, vector_rank, ...)
      + bonus(标题/文件名精确匹配)
      + bonus(人工标签匹配)
      + bonus(收藏优先模式)
```

PRD 的 `0.5/0.3/0.15/0.05` **不作线性公式系数**,而是调参时的初始直觉(文本路召回结果在 RRF 中天然倾向靠前;权重体现在每路 top-N 大小与各 bonus 系数上)。

### 评测集时机:延到阶段二

PRD §8.3 想要 30–50 个查询的人工相关性标注来调参。决策:**阶段二再建评测集**。阶段一只有全文路(无向量召回),没东西可调;阶段二向量路接进来后,用同一批评测集一次性把 RRF 的 `k` 与各 bonus 系数调出来。

## 理由

- **量纲无关**:RRF 只看排名,天然解决两路分数不可比,是搜索领域对"异构召回融合"的事实标准(Elasticsearch、LangChain、LamaIndex 默认)。
- **适合分页**:每路独立取 top-N 再融合,不依赖全量结果集统计量,翻页稳定。
- **保留业务意图**:结构化加分把 PRD 想要的"精确匹配加分、人工优先、收藏加权"语义完整保留,且不强行把 `ts_rank_cd` 与 cosine 塞进一个线性组合。
- 代价是丢失"绝对相关度"信息,但搜索界面给用户看的是排序而非绝对分,这个代价基本不痛。

## 后果

- **正面**:融合方法数学正确;调参空间清晰(`k`、各路 top-N、bonus 系数);分页稳定。
- **负面**:需要构建评测集(30–50 查询 + 人工标注)才能把参数从默认值调优,这是阶段二的工作量;每路 top-100 意味着查询时要合并 200+ 条候选,有轻微计算开销(2 万页规模可接受)。
- **写入路径影响**:`slide_embeddings` 和 `text_search` 只需各自能独立产出 top-N 排序结果,无需在写入时预计算融合分数。融合纯在查询时在线进行。
