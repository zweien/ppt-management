# ADR-0008:阶段三 —— 版本识别、页面变化匹配与当前版本

- **状态**:已接受
- **日期**:2026-07-29
- **决策者**:工程讨论确认
- **取代**:无(补充 PRD §10 的算法落地)

## 背景

阶段三的版本与复用增强需要两个算法决策,PRD 只给了输入信号(§10.1)和判定原则(§10.3),未定具体算法。这两个决策返工成本高(改算法要重算所有版本对的匹配),先敲定。

- **版本识别**:上传新文件时,如何建议"它可能是某已有文件的新版本"
- **页面变化匹配**:两个版本之间,如何判定页面是未变化/文字修改/视觉修改/新增/删除/重排

单页导出算法已在 ADR-0002 定(关系图遍历 + 复制或拒绝 + pHash),本 ADR 不重复。

## 决策

### 1. 版本识别:页面指纹集合的 Jaccard 相似度(建议,非强制)

PRD §10.1 明确"自动判断只提供建议,用户最终手动选择"。故算法不必精确,只需给合理候选 + 可解释。

**算法**:
- 每个版本的"指纹签名"= 该版本所有 slide 的 `fingerprint`(原生文字归一化哈希,阶段一已生成)的**集合**。
- 候选相似度 = 新版本指纹集合 与 已有版本指纹集合的 **Jaccard 相似度** `|A∩B| / |A∪B|`。
- **辅助信号**:页数接近度(差值 ≤ 2 视为接近)、文件名相似度(编辑距离)。
- **建议阈值**:Jaccard ≥ 0.5 → 建议"可能是新版本",按相似度降序排列候选;用户可接受建议或选"新文件"。
- 阈值**部署级可配**。

**理由**:Jaccard 量纲明确、计算 O(n)、可解释("你 12 页里有 10 页与《X》相同")。无需 ML/向量。原生文字指纹已是真值(CONTEXT.md「原生结构层」),用它做主信号比文件名可靠得多。

**不选**:文件名相似度单独判断(易误判重命名);整体内容 embedding 相似度(需要向量,且粒度太粗)。

### 2. 页面变化匹配:指纹精确匹配 + pHash 视觉比对 + 序号对齐

PRD §10.3 给了 5 种状态。用确定性算法判定,不需 ML。

**算法**(对版本 A → 版本 B 的每页):

1. **未变化**:A 的某页 fingerprint 在 B 中存在(原生文字哈希一致)。
2. **文字/视觉修改**:A 的某页 fingerprint 在 B 中**不存在**,但与 B 中某页的 `visual_phash`(感知哈希)Hamming 距离 ≤ 阈值(如 8)。
   - 进一步区分:若 B 对应页 fingerprint 也变 = 文字修改;若仅 visual_phash 变 = 视觉修改。简化:MVP 阶段二/三统一标"修改",展示前后缩略图。
3. **新增**:B 中存在但 A 中无任何匹配(指纹 + pHash 都不匹配)。
4. **删除**:A 中存在但 B 中无任何匹配。
5. **重排**:A、B 中都存在的页面(fingerprint 一致),但 page_no 不同。

**匹配策略**:优先 fingerprint 精确匹配(未变化/重排),剩余未匹配页用 pHash 做最近邻匹配(修改),最后无匹配的归新增/删除。

**前置条件**:`visual_phash` 字段阶段一已建(空),阶段三需在渲染任务里填充(用 imagehash 库对缩略图算 64-bit pHash)。

**输出**:写入 `version_slide_matches(from_slide_id, to_slide_id, match_type, score)` 表。match_type ∈ {unchanged, modified, added, deleted, rearranged}。

### 3. 当前版本切换 + 包含历史版本搜索

- **current_version_id 切换**:`POST /presentations/{id}/versions/{vid}/set-current`(PRD §14.1 已设计端点)。
- **默认搜索仅当前版本**:hybrid_search 已有此约束(`Presentation.current_version_id == PresentationVersion.id`)。
- **包含历史版本**:搜索接口加 `include_historical=true` 参数,放开当前版本过滤。UI 在搜索页加开关。

## 后果

- **正面**:版本识别可解释、页面匹配确定性;用户上传时可主动关联版本,形成版本链;可查看版本间变化;单页导出可复用(ADR-0002)。
- **负面**:页面匹配依赖 `visual_phash`,需在渲染任务填充(增量工作);版本识别阈值需在真实数据上标定;多版本文件需用户主动创建(自动关联仅建议)。
- **数据模型**:新增 `version_slide_matches` 表(迁移);`slides.visual_phash` 填充逻辑加入 render 任务。
